**4. README 的核心需求与需要补齐的设计**

README 要求日志只参与训练数据构造和质量验证，模型和网关推理只读取网络流量；日志格式应适配化；日志延迟和前后窗口长度配置化；按目标事件分别构建 P/U，其他事件进入 U；清洗自动、对称、逐包可审计；支持多 IP、多事件；优先按会话划分；网关执行滑窗、阈值判断及重复事件合并。当前阶段排除 SHAP/LIME、蒸馏、规则提取等研究。

实施前在设计文件中补齐以下定义，避免照搬示例产生新的错误：

- **区分时间语义。** HA last_changed、平台事件产生时间、日志写入时间、接收时间和手机命令发出时间不能统称为真实事件时间。优先保留来源语义，并分别处理时钟偏移和观测延迟。手机点击时间也不等于设备完成状态变化的时间。
- **日志必需的边界。** 自动生成 P 必须有目标事件日志与合格证据；未记录事件的流量可以作为 U。日志缺失或解析失败的整场会话不得悄悄当作背景 U 正式导出，应停止正式构造并记录原因。人工独立审计真值可以另行生成，不冒充自动弱标签。
- **延迟范围与窗口长度。** README 的 delay=10、before=5、after=5 只是示例，会产生 10 秒候选区间；网关示例为 4 秒滑窗。两者需要显式衔接，不能把一个宽区间中的所有 4 秒子窗口标为 P。
- **多事件冲突。** 某其他事件窗口只有不与当前目标 P/保护区冲突时才能进入 other_event U；严重混合窗口进入冲突审计或隔离区。支持多事件不意味着所有事件互斥。
- **U 与真负例。** 验证/测试包含背景和其他事件不等于其目标事件缺失已经得到证明。标签来源和可信度必须单独记录。

**5.2 分离时钟校正与延迟估计**

建议使用以下统一定义：

```text
t_log_capture = t_log_source + clock_offset
t_event_estimated = t_log_capture - delay
固定延迟候选区间 = [t_event_estimated - before, t_event_estimated + after)
区间延迟候选区间 = [t_log_capture - delay_max - before,
                     t_log_capture - delay_min + after)
```

这里 clock_offset 定义为“采集主机时钟减去日志来源时钟”，delay 定义为“该来源所选日志时间相对目标事件的观测延迟”。clock_offset_uncertainty 单独记录，按其上下界扩展候选区间。所有实现统一左闭右开，纳秒计算后再生成展示时间。

延迟按 source/device/event 配置，使用 pilot 或训练会话中可信的校准观测估计；保存校准 session、样本量、中位数/分位数、范围和版本。禁止利用测试指标搜索延迟或窗口参数。无法校准时只生成 uncertain 候选或隔离记录，不能静默令 delay=0 后当作可信 P。命令时间可作为校准参考或旧基线锚点，其意义和局限明确标注。

固定延迟阶段建议先采用 before=2、after=2 的 4 秒候选窗口，与当前基线长度兼容；这是初始配置建议，不是所有设备的普适参数。README 的 10 秒延迟示例不应成为默认实测值。

延迟范围较宽时保留事件候选包络，再用与部署一致的 4 秒子窗口和可配置步长覆盖它；P 监督附着于父 Bag“至少一个子窗口含事件”，不下传到每个子窗口。U 也匹配父 Bag 时长、子窗口数量和取样规则。该路线在 MIL 阶段实现；短期 MLP 基线只运行固定长度合格视图，宽包络不混入 4 秒基线。另一种更长部署窗口方案需要先确定并冻结训练/推理共同规则，不能静默混用。

**验收：** 固定延迟、区间延迟、时钟偏移及其不确定度都有精确算例；越界窗口和不能对齐的候选有原因码；保存原日志时间、校正时间、估计事件时间、区间及策略版本。

**5.3 按目标事件重构 P/U**

将 LX04 事件判定、窗口生成、实例分配、清洗、导出拆成公共组件；保留现有 PCAPNG 解析器和不覆盖非空审计快照的机制。公共构造器只接收规范事件、CaptureSpec、DeviceSpec、WindowPolicy、EvidencePolicy。

每个 target_event 构造自己的视图：目标合格事件形成 P；其他已知事件形成 other_event U；保护区外的连续自然流量形成 background U；无法确认的尝试、日志可能漏报区形成 uncertain_event U。单独保留 target_event 与 source_event_type，不能把当前目标名称改写成源事件类型。不同任务的背景 U 可以复用缓存，但不能仍然复用一份完整 U 而省略其他事件。

P 要求来源日志和成功证据、完整捕获区间、设备相关流量、无严重已知冲突及无空 Bag。保留现有弱标签可信度，未经独立复核不得把 is_strict_gold=false 改为 true。双向流量可作为可配置质量项，不对所有新设备强行要求双向。

P/U 采用相同窗口和实例处理规则；记录未覆盖时间、空窗口、失败重试、持续状态流量和冲突。空窗口从分类训练清单排除时，部署回放仍必须记录其存在和处理策略。其他设备事件发生但目标设备没有相关流量时，不伪造目标设备 Bag，其范围进入质量报告。

对当前无新冲突的 4 秒 LX04 基线，结构回归预期为：播放任务 20 P，U 在原 51 个基础上加入 20 个成功暂停窗口；暂停任务对称；any_playback_change 仍为 40 P 和 51 U。即单事件 U 预期为 71。改用新延迟与窗口策略后计数允许改变，但每项变化都必须有事件/窗口原因码。

**验收：** 当前播放/暂停数据验证其他事件进入对应 U；同一任务 P/U 不重复包；新设备增配 Adapter 和配置即可导出；多事件、重试与冲突测试不依赖历史固定 SESSION_ID。

**8. P1：保留基线，逐步增加 MIL 与 nnPU**

依次实现 AE + Mean/Std + Logistic Regression、现有 AE + Mean/Std + MLP + BCE、AE + MIL + BCE、AE + MIL + nnPU。前面三个仅将 U 当临时伪负例；BCE 基线的用途与限制在运行配置和指标中明确。所有模型共享数据版本、会话划分和特征版本。

MIL 在 AE 嵌入后增加实例或固定子窗口分类器、mask 与 Bag pooling，先完成一种明确实现的 pooling。若选 Noisy-OR，应使用稳定数值计算并检查 Bag/子窗口数量对概率的影响；不能只修改模型名称便宣称实现 MIL。宽延迟包络采用父 Bag 标签与子窗口聚合，避免把每个子窗口错误标 P。

nnPU 的 Bag 级目标可写为：

```text
R = pi * E_P[loss(g(B), 1)]
    + max(0, E_U[loss(g(B), 0)] - pi * E_P[loss(g(B), 0)])
```

这里 pi 是所定义训练采样分布下的目标事件 Bag 先验，不能用 P_count/(P_count+U_count) 直接代替。记录先验来源、训练内估计或敏感性范围、风险项和优化设置。实现与 [Kiryo 等的 nnPU 原论文](https://proceedings.neurips.cc/paper/2017/file/7cce53cf90577442771720a370c3c723-Paper.pdf) 对照，该论文设定 P 来自正类条件分布，U 来自边缘分布并使用类别先验。

对本项目需要额外审计：日志成功门槛可能选择特定 P；排除已知 P 保护区、按 other_event 过采样以及人为控制事件频率，会改变 P/U 采样分布。这是根据论文设定与本项目构造策略做出的推论。执行新 README 的 U 策略时保留采样概率、来源分层和权重；若不能证明相应采样假设成立，把 nnPU 作为带已说明假设的实验方法，不宣称获得无偏真实风险。必要时另提供自然连续滑窗审计池检查分布偏差，不把其未知样本改成标注负训练 Bag。

**验收：** BCE/nnPU 名称与实际损失一致；MIL 接收变长实例并正确 mask；极端 Bag 长度、单实例和空窗处理有测试；nnPU 风险项和先验有记录；比较使用相同会话及独立审计协议。

**9. P1：无日志推理和连续 PCAP 回放**

新增 inference/，先实现离线原始 PCAP 连续回放，无需立即集成实体网关。输入仅为 PCAP/包流、DeviceSpec、固定窗口/步长配置、冻结的 CleaningPolicy、scalers、AE、分类器与每个目标事件阈值；不加载 actions、HA history 或日志时间。
