## 本次发现与最小修复

首轮 Linux 定向测试 28 passed / 2 failed，原日志 `python-focused.log` 保留：

1. 孤儿子进程在 reconcile 的早期检查后才真正退出，后续 cleanup 分支直接标记中断，却没有释放所属死租约。修复为最终确认无活 worker/child 后，先执行按任务/创建身份/lease ID 校验的精确租约释放，再标记中断；已有活子进程保护不变。新增确定性的异步退出回归测试。
2. 原测试保存的 POSIX `terminate()` 仍调用被 mock 的 `send_signal()`，造成测试清理超时。修复测试 teardown 恢复原信号方法；挂起 capture 替身显式忽略 SIGINT 并发送 ready，确保测试真正模拟等待显式强制停止的进程。

修复后 Windows 与 Linux 定向测试各 31 passed，Ruff 通过。共用源码于北京时间 **2026-10-06 20:56:33** 冻结，再按桌面工程版本 0.1.1 的锁同步两平台；Python core 自身版本保留 0.1.0，以 wheel 内容 SHA 区分。

## 保留的验收边界

- WSL/WSLg 不代替原生 Ubuntu 桌面、USB、SDK 最小集合、udev/抓包权限或真实正式接口双向流量验收。
- 合成 SIGINT 测试不等于 Linux 实际 Dumpcap 排空，不等于真实 PCAP、强制关机或注销演练。
- 当前 Deb 的实际载荷包含许可材料，但 `license_clearance_complete=false`；具体源码提供和剩余材料核对继续由许可证记录说明，不把 SBOM 数量当作完整授权结论。
- 不将缓存构建、隔离 dev 依赖补齐或 WSLg 运行描述成干净原生机器离线安装、升级/回退、卸载或已取消的 9.1 多入口验收。
- 原生 Ubuntu 相关任务由主任务保持待验收，不在本报告勾选。
