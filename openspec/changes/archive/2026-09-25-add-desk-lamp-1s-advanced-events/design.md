# Design

## Context

动机见 [proposal.md](proposal.md)，行为契约见两份新增规格。当前 `automation/src/iot_exp/models.py` 以 `DeviceState` 枚举表达开关和播放状态，`EventSpec` 固定为二态转换，且一个实验不允许重复 `event_type`。`orchestrator.py` 按此状态选择事件，`ActionRecord` 也只记录单一的前后枚举状态。米家台灯适配器目前只识别“开灯/关灯”；干运行模拟与控制台事件名称也依赖现有四种事件。`automation/experiment/mi_desk_lamp_1s.yaml` 的已验证内容仅为开关，仓库中没有可确认四类新控件范围与状态标记的台灯页面证据。

## Goals / Non-Goals

**Goals:**

- 在保留现有开关和音箱行为的基础上，让一次事件具有明确的目标维度、目标值、前置条件和独立的操作前后页面观察。
- 使多个亮度值、色温值和六个情景目标能在同一实验中分别计数、调度与追溯；没有可信回读时明确失败。
- 让开发会话和控制台正确呈现目标参数及 `app_ack_only` 的证据级别。

**Non-Goals:**

- 本阶段不启用 HA 对账、正式抓包，也不以 App 页面回执证明灯具物理输出或独立设备状态。
- 不改造音箱的图标识别，也不把米家页面细节推广到通用编排层。

## Decisions

### 1. 事件身份与配置

保留现有四种二态事件配置，新增 `set_brightness`、`set_color_temperature`、`select_scene` 和 `set_focus_mode` 四种带目标的事件。目标分别为数值、数值、稳定情景 ID 和布尔值；调节范围、单位、允许误差及六个情景 ID 在台灯实验配置中显式声明。对新事件按类型验证目标形态、边界与前置条件，不接受缺失或不匹配的目标。事件身份采用 `(event_type, target)`，会话的计划数和重复次数以该身份计数；同一身份重复配置仍拒绝。现有开关与音箱 YAML 不需迁移。

选择这一方式是因为六个情景按钮属于同一类操作，而同一亮度维度也需要多个目标值才能重复产生真实变化。为每个目标增加枚举事件类型会使模型和控制台膨胀；把数值硬塞进 `DeviceState` 则会丢失单位、误差和维度。

### 2. 观察与适配器边界

引入带 `dimension`、`value`、`unit`、`observed_at_unix_ns`、`source` 和证据文件引用的页面观察对象。参数化事件由适配器提供读取目标维度、执行目标动作、等待目标回读的能力；编排器只比较值和误差，不解释米家控件。现有 `read_state`、`perform_event`、`wait_for_ack` 二态接口保持可用，旧适配器不必伪造数值能力。未实现参数化能力的适配器收到对应事件时在执行前报明确错误。

亮度和色温读取 App 文字数值，再依据实测范围换算滑动位置。情景配置建立六组“按钮定位＋亮度/色温预设值”的一一映射；真机 XML 的六组按钮均不提供有效选中属性，因此运行时不依赖图标截图或按钮 `selected`。专注模式使用二级设置页的页面标记和开关 `checked` 等当前状态，读取与操作后返回设备页。无法识别时返回未知并保存诊断。

统一改写所有适配器接口是可行备选，但会扩大音箱和已验证开关路径的回归面；本阶段采用增量接口。

### 3. 调度与真实变化判定

运行器在候选目标的相关维度上读取当前状态，只选择满足前置条件且当前值尚未达到目标的事件；等待后、命令前再次读取，若动作前状态不可读则不发命令。亮度、色温和情景事件默认要求台灯已开启；专注开关以其本身状态为前置判据。数值用声明误差比较，情景由两项数值在误差内唯一匹配预设，专注用开关当前标记比较。混合实验先完成可执行的亮度/色温目标，再进入情景按钮；若剩余目标均无法合法执行，记录原因并以未完成会话结束。

不能以动作返回、滑块到达预计坐标或上一次命令推断成功。状态已等于目标时记录无变化，另选可执行事件；动作后目标未回读成功时保留失败尝试及诊断。放宽“必须有实际变化”会提高表面成功率，但破坏事件标签的真实性，因此不采用。

### 4. 日志、证据与校验

在现有 `ActionRecord` 上增加可选的目标维度、目标值、单位、允许误差、操作前后观察值及证据引用；旧记录字段和解析保持兼容。新事件在命令前后各保存与同一 `event_id` 关联的页面 XML/截图或等效可复查证据，并记录观察时间和来源。失败也保留页面诊断；重试仍生成新事件 ID。开发模式下的成功分类为 `app_ack_only`，不调用 HA 才能判定新事件，也不写 `confirmed`。

会话校验对新事件追加目标范围、前后确有变化、后值命中目标、时间顺序、证据文件存在及事件 ID 唯一性检查；保留旧会话的既有校验语义。质量报告按配置的事件身份计算计划数和结果，不用同类事件的一个目标覆盖另一个。控制台模板和事件列表显示目标值/模式，而不是把六个情景都显示成相同的 `select_scene`。

只保存最终值是更简单的备选，但无法复核“已在目标值”“动作后变化”或页面读取来源，因此不采用。

## Risks / Trade-offs

- **App 无法提供可信的数值或选中标记** → 先用只读页面检查确认 XML、无障碍属性与截图；情景按钮无选中属性时使用逐一实测的唯一亮度/色温预设回读。数值不可读或匹配不唯一时保持未知、保留证据，不将事件标为成功。
- **滑动条离散步进或动画造成回读误差** → 从真实控件确定范围和步进，配置合理误差并在超时内轮询；保存目标、回读值和误差，不能用宽容差掩盖错误控件。
- **情景切换可能连带改变亮度和色温** → 每个事件以其目标维度判定；必要时在证据中保留其他可读状态，不假定这些维度互不影响。
- **设置页导航或 App 升级导致状态误读** → 页面标记、当前值标记与动作控件分离，限定恢复次数，失效时停止盲操作并保存 XML/截图。
- **App 页面状态与灯具物理状态可能不一致** → 明确 `source=vendor_app` 和 `app_ack_only`；物理真实性超出本阶段可证明范围。
- **既有脚本和控制台仍按二态字段读取记录** → 新字段采用可选扩展，旧配置回归测试通过后再启用新的台灯实验模板，并同步控制台显示。

## Migration Plan

1. 先扩展模型与运行器，同时保持现有 YAML、旧记录和开关/音箱模拟测试可运行。
2. 新建米家台灯高级事件实验 YAML，不覆盖已验证的开关实验。通过只读页面检查填入实际范围、六个情景 ID、选择器和专注页标记；未核实前不得以占位值启动真机新事件。
3. 完成台灯适配器、模拟能力、会话校验和控制台显示后，运行静态检查、必要测试及新实验的无真机干运行。
4. 若设备与 App 可用，在不抓包模式下逐类进行一次真实操作与回读核验；失败记录保持原样，并在修复后使用新会话 ID。未完成真机核验时只报告逻辑开发完成，不声称控件已在真机验证。
5. 回退时停用高级实验模板即可继续使用原开关模板；原有会话产物不重写或删除。
