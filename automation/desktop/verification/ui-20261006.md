## 本轮修复

- 前端强制停止选项原先以 `updated_at_ns` 判断等待期，清理进度更新会重新开始计算；现在优先使用 `stop_requested_at_ns`，旧记录仍使用原更新时间作为兼容回退。新增两项回归，验证清理更新不重置等待期、不到 60 秒仍不可强制及旧记录兼容。
- main 使用 backend 的 `hasExited` 同时识别退出码与信号退出，避免把已信号退出的后台当作活进程；状态界面从当前后台健康响应同步 recovery 状态。
- 安全退出页改为按 draining/recovery 状态说明日志保存或残留进程核查；不再在退出时显示首次初始化说明，零个所属进程时显示仍在保存日志。

前端测试 **14 项通过**，TypeScript 检查与生产构建通过。桌面普通 Node 测试 **6 项通过**；7 个真实后台 integration 场景在该普通命令下按开关跳过，不能把这次普通测试当作它们已通过。

## 范围

本机 UI 证据可支持 6.5 的本轮范围验收。6.3 的文本、图片和 PDF 预览部分应与负责原文件能力的验证记录合并判断；本脚本没有调用 Shell 原文件打开/目录定位。这些模拟与故障路径不代替 Windows/Ubuntu 真机、正式网络、干净系统安装或已被用户取消的升级/卸载、跨入口并行专项验收。
